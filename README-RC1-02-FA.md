# Carrtell RC1-02 — Store Complete

این پچ زیرساخت اصلی فروشگاه و Checkout را یکپارچه می‌کند.

## قابلیت‌های تکمیل‌شده

- ثبت اتمیک سفارش از طریق RPC سرور
- کنترل موجودی و قیمت نهایی از دیتابیس، نه اطلاعات مرورگر
- رزرو موجودی هنگام ثبت سفارش
- جلوگیری از فروش بیش از موجودی در درخواست‌های هم‌زمان
- بازگردانی موجودی سفارش لغوشده با تابع مستقل
- اقلام سفارش مستقل در `order_items`
- ثبت گردش موجودی در `inventory_movements`
- کد تخفیف با تاریخ، سقف، حداقل خرید، سقف هر کاربر و محدودیت کل
- محاسبه دوباره تخفیف هنگام ثبت سفارش برای جلوگیری از دستکاری
- ثبت استفاده از کد تخفیف داخل تراکنش سفارش
- پرداخت آزمایشی و نهایی‌سازی idempotent
- Snapshot امن سفارش برای صفحه پرداخت و فاکتور
- RLS مشتری و مدیر
- نمایش و حذف کد تخفیف در Checkout
- اصلاح خطای TypeScript مربوط به `initialized` در Auth Guard

## نصب

1. از پروژه فعلی بکاپ بگیرید.
2. محتویات ZIP را در ریشه پروژه کپی و فایل‌های هم‌نام را Replace کنید.
3. فایل زیر را در Supabase SQL Editor اجرا کنید:

```text
supabase/migrations/202607230003_rc1_02_store_complete.sql
```

4. در PowerShell:

```powershell
cd D:\carrtell\Carrtell-v0.2-current\project
npm install
npm run typecheck
npm run dev
```

## تست اصلی

1. با کاربر واردشده یک محصول موجود به سبد اضافه کنید.
2. کد آزمایشی `CARTELL10` را اعمال کنید. حداقل خرید آن ۵۰۰٬۰۰۰ تومان است.
3. سفارش را ثبت کنید و وارد صفحه پرداخت شوید.
4. پرداخت آزمایشی را انجام دهید.
5. در Supabase بررسی کنید:
   - `orders`
   - `order_items`
   - `payments`
   - `inventory_movements`
   - `discount_usages`
6. موجودی محصول باید هنگام ثبت سفارش کاهش یافته باشد.

## نکات امنیتی

- قیمت، تخفیف و موجودی سمت سرور محاسبه می‌شود.
- `total_amount` ارسالی مرورگر مبنای ثبت نیست.
- کاربر فقط سفارش‌های خودش را می‌بیند.
- مدیر از طریق نقش دیتابیس به کل سفارش‌ها دسترسی دارد.

## بازگردانی موجودی سفارش لغوشده

```sql
select public.carrtell_release_order_inventory(
  'ORDER_UUID',
  'لغو سفارش توسط مدیر'
);
```

این تابع idempotent است و موجودی را دوبار برنمی‌گرداند.
