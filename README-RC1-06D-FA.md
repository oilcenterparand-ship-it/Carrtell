# Carrtell RC1-06D — ورود پایدار، پرداخت سرویس و جستجوی هوشمند

## تغییرات
- ورود و تأیید موبایل قبل از شروع رزرو سرویس.
- بازگشت کاربر پس از OTP به همان مسیر قبلی، از جمله `/book` و `/cart`.
- استفاده از نشست پایدار Supabase؛ تا زمانی که کاربر خروج نزند، سایر بخش‌ها دوباره OTP نمی‌خواهند.
- شماره موبایل تأییدشده در رزرو به‌صورت خودکار بارگذاری و قفل می‌شود.
- پس از ثبت اطلاعات سرویس، کاربر ابتدا وارد مرحله پرداخت می‌شود.
- شماره درخواست فقط بعد از پرداخت موفق نمایش داده می‌شود.
- پرداخت سرویس در این نسخه آزمایشی است و ساختار برای اتصال درگاه اصلی آماده شده است.
- دکمه مشاهده وضعیت بعد از پرداخت، کاربر را به `dashboard#orders` می‌برد.
- نوار پایین هنگام باز شدن کیبورد یا پنجره انتخاب خودرو مخفی می‌شود.
- دکمه‌های تأیید/انصراف انتخاب خودرو بالاتر از Safe Area و قابل دسترس می‌مانند.
- ارسال جستجو دیگر به صفحه خانه برنمی‌گردد و به `/shop/all-products` می‌رود.
- جستجوی لحظه‌ای محصولات و خودروها با تحمل خطای تایپی و یکسان‌سازی حروف فارسی.
- نتایج بر اساس دسته محصول و خودروهای پیشنهادی گروه‌بندی می‌شوند.

## نصب
1. محتویات ZIP را در ریشه پروژه Replace کنید.
2. فایل زیر را در Supabase SQL Editor اجرا کنید:
   `supabase/migrations/202608010001_rc1_06d_service_auth_payment.sql`
3. اجرا کنید:
   `npm run typecheck`
   `npm run build`
4. محتوای `dist` جدید را در `public_html` جایگزین کنید.

## تست
1. در حالت خروج، `/book` را باز کنید؛ باید به ورود OTP برود.
2. بعد از ورود باید مستقیم به رزرو برگردد.
3. رزرو را کامل کنید؛ قبل از نمایش شماره درخواست باید صفحه پرداخت دیده شود.
4. پرداخت آزمایشی را بزنید؛ سپس شماره درخواست و دکمه وضعیت نمایش داده شود.
5. روی جستجو عبارت ناقص یا دارای اشتباه کوچک وارد کنید؛ پیشنهادهای محصول و خودرو باید لحظه‌ای ظاهر شوند.

## وضعیت بررسی
`npm run typecheck` بدون خطا اجرا شد. Build در محیط تحویل به‌علت مجوز فایل اجرایی Vite اجرا نشد؛ روی ویندوز پروژه قابل اجراست.
