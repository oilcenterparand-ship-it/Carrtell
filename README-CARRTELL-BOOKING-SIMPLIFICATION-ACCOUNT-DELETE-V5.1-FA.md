# Carrtell V5.1 — رزرو خلوت + OTP قبل پرداخت + حذف حساب

مبنای توسعه: GitHub branch `sprint/guest-checkout-search-car-picker` commit `6157a7b`.

## تغییرات رزرو موبایل
- مرحله ۵ فقط شامل نام مشتری و انتخاب موقعیت است.
- شماره موبایل و OTP از مرحله اطلاعات/آدرس حذف شده‌اند.
- در نقشه فقط دکمه «موقعیت فعلی من»، خود نقشه و دکمه تأیید موقعیت باقی مانده است.
- عنوان‌ها، متن‌های راهنما، جستجوی مکان و باکس «آدرس تشخیص داده‌شده» از اطراف نقشه حذف شده‌اند.
- توضیحات سرویس‌کار به مرحله ۶ منتقل شده است.
- مرحله ۶ فقط خلاصه ضروری، توضیحات اختیاری، تأیید شماره و مبلغ نهایی را نشان می‌دهد.
- OTP فقط درست قبل از پرداخت انجام می‌شود.
- تا شماره تأیید نشده، دکمه ثبت رزرو/پرداخت غیرفعال است.
- کاربر لاگین‌شده‌ای که همان شماره حسابش را دارد دوباره OTP نمی‌گیرد.

## حذف حساب کاربری
مسیر `حساب من > پروفایل > حذف حساب کاربری` حفظ شده است.
روند: درخواست حذف → OTP → تأیید کد → Edge Function حذف حساب.

Backend:
- Auth user حذف می‌شود.
- داده‌های شخصی قابل حذف پاک می‌شوند.
- سفارش‌ها و سوابق مالی ناشناس می‌شوند و کورکورانه حذف نمی‌شوند.
- مدیر و سرویس‌کار از این مسیر حذف نمی‌شوند.
- Service Role فقط Server-side باقی می‌ماند.

### Deploy اجباری حذف حساب
اگر قبلاً Deploy نشده یا دکمه عمل نمی‌کند، این دستور را اجرا کنید:

```powershell
npx supabase functions deploy customer-account-delete --no-verify-jwt
```

## QA Agent
حالت `PERSONAS` علاوه بر Customer/Admin/Technician، تست Regression رزرو کامل را هم اجرا می‌کند:

`service -> vehicle -> product/package -> time -> location -> OTP before payment -> payment`

در این تست بررسی می‌شود:
- مرحله ۵ input موبایل ندارد.
- «آدرس تشخیص داده‌شده» وجود ندارد.
- توضیحات سرویس‌کار در مرحله ۵ نیست.
- OTP در مرحله ۶ دیده می‌شود.
- پرداخت قبل از تأیید موبایل غیرفعال است.
