# Carrtell V4.9.1 — Driver App + Service Operations

این پچ ادامه‌ی V4.9 است و به‌صورت cumulative بسته شده تا فایل‌های V4.9 موردنیاز را هم همراه داشته باشد.

## تغییرات اصلی

### پنل سرویس‌کار
- مسیرهای `/driver`, `/driver/dashboard`, `/driver/jobs/:id` کاملاً خارج از SiteLayout هستند؛ Footer و منوی فروشگاه داخل پنل سرویس‌کار رندر نمی‌شوند.
- روند مأموریت مرحله‌ای و واضح است: مأموریت جدید → قبول → در مسیر → رسیدن → انجام سرویس → پایان.
- مرحله فعلی با رنگ زرد و برچسب «مرحله فعلی» مشخص می‌شود؛ مراحل انجام‌شده سبز می‌شوند و مراحل آینده غیرفعال/کم‌رنگ هستند.
- دکمه اصلی فقط اقدام بعدی را انجام می‌دهد تا سرویس‌کار نتواند ترتیب مراحل را اشتباه کند.
- با زدن «شروع حرکت»، ابتدا وضعیت مأموریت `en_route` ثبت می‌شود و سپس Neshan با مقصد مشتری باز می‌شود.
- اگر دسترسی Location داده شود، مختصات فعلی سرویس‌کار به عنوان مبدا و مختصات مشتری به عنوان مقصد استفاده می‌شود؛ در صورت عدم دسترسی، مقصد مشتری در نشان باز می‌شود.
- دکمه مستقل «مسیریابی با نشان» نیز داخل جزئیات مأموریت قرار دارد.

### پنل مدیریت
- `/admin/dispatch` تبدیل شده به «صف تخصیص سرویس‌کار» و تمرکز آن روی سفارش‌های پرداخت‌شده و آماده اعزام است.
- سفارش پرداخت‌شده فقط وقتی `payment_status=paid` باشد در تب اصلی آماده تخصیص دیده می‌شود.
- مسیر جدید `/admin/service-operations` اضافه شده؛ وضعیت ماموریت‌ها را به شکل ستون‌های عملیاتی نمایش می‌دهد:
  - منتظر قبول
  - قبول شده
  - در مسیر
  - رسیده
  - در حال سرویس
  - تکمیل شده
- مدیر از صفحه تخصیص فقط سرویس‌کار/خودرو را انتخاب می‌کند و ادامه روند را در صفحه «روند مأموریت‌ها» مشاهده می‌کند.

## SQL
این پچ SQL جدیدی نسبت به V4.9 ندارد. فایل migration V4.9 داخل ZIP قرار گرفته و idempotent است:

`supabase/migrations/202608200002_paid_order_to_service_crm.sql`

اگر V4.9 را قبلاً نصب و SQL آن را اجرا کرده‌ای، دوباره اجرای SQL لازم نیست.

## نصب
ZIP را در ریشه پروژه Extract و Replace کن:

`D:\carrtell\Carrtell-v0.2-current\project`

سپس:

```powershell
npm run typecheck
npm run build
```

اگر SQL V4.9 هنوز اجرا نشده، محتوای migration بالا را یک بار در Supabase SQL Editor اجرا کن.

## تست

```powershell
$env:CARRTELL_ADMIN_USERNAME="admin"
$env:CARRTELL_ADMIN_PASSWORD="12345678"
$env:CARRTELL_TECH_USERNAME="service"
$env:CARRTELL_TECH_PASSWORD="12345678"
.\agent.ps1 PERSONAS
```

تست دستی سرویس‌کار:
1. `/driver/login`
2. ورود با حساب سرویس‌کار
3. باز کردن مأموریت
4. قبول مأموریت
5. شروع حرکت → باید Neshan باز شود
6. برگشت به Carrtell
7. «رسیدم به محل»
8. «شروع سرویس»
9. ثبت عملیات و پایان سرویس

تست دستی مدیریت:
1. `/admin/dispatch` → سفارش‌های پرداخت‌شده آماده تخصیص
2. انتخاب سرویس‌کار + خودرو اختیاری
3. «تخصیص و ارسال مأموریت»
4. `/admin/service-operations` → مشاهده حرکت کارت مأموریت بین مراحل

## نکته Build محیط تحویل
TypeScript typecheck روی سورس PASS شده است. Build در محیط تحویل لینوکسی به دلیل node_modules ویندوزی ZIP و نبود optional binary لینوکس Rollup قابل اجرا نبود؛ Build نهایی باید روی ویندوز پروژه اجرا شود.
