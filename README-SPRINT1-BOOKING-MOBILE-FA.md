# Sprint 1 — اصلاح مسیر رزرو سرویس در موبایل

## مبنا
این Sprint روی فایل `Carrtell-current-source.zip` انجام شده است.

## تغییرات انجام‌شده
- الزام ورود و تأیید شماره موبایل پیش از ورود به مسیر رزرو، با استفاده از مسیر موجود `/login-otp`.
- جلوگیری از عبور از مرحله زمان بدون انتخاب بازه دارای ظرفیت.
- پذیرش موقعیت انتخاب‌شده روی نقشه به‌عنوان آدرس معتبر، حتی بدون تایپ متن آدرس.
- حذف پیام سبز تکراری «شماره موبایل تأیید شده است» در مرحله آدرس.
- ساده‌سازی عنوان و هدر رزرو در موبایل.
- تبدیل نمایش مراحل به حالت فشرده و خوانا در موبایل.
- اضافه شدن نوار ثابت ادامه/بازگشت در پایین صفحه موبایل.
- بزرگ‌تر شدن ناحیه لمس دکمه‌های اصلی و بهبود فرم‌های موبایل.

## فایل‌های تغییرکرده

## نصب
1. از پروژه فعلی نسخه پشتیبان بگیرید.
2. محتوای Patch را در ریشه پروژه جایگزین کنید.
3. در PowerShell داخل مسیر پروژه اجرا کنید:

```powershell
npm install
npm run typecheck
npm run build
npm run dev
```

## تست دستی
1. در حالت خارج‌شده از حساب، مسیر `/book` را باز کنید.
2. باید به `/login-otp` منتقل شوید.
3. شماره موبایل را تأیید کنید؛ باید دوباره به `/book` برگردید.
4. در مرحله اول خودرو و حداقل یک خدمت را انتخاب کنید.
5. در مرحله دوم بدون انتخاب بازه زمانی روی ادامه بزنید؛ باید خطا نمایش داده شود.
6. در مرحله آدرس فقط موقعیت را روی نقشه انتخاب کنید؛ ادامه باید ممکن باشد.
7. در عرض موبایل بررسی کنید دکمه‌های مرحله قبل/ادامه پایین صفحه ثابت و قابل لمس باشند.
8. رزرو را ثبت کنید و انتقال به `/service-payment/:requestId` را بررسی کنید.

## وضعیت تست
- `npm run typecheck`: موفق و بدون خطا.
- Build در محیط تحویل به‌دلیل خطای Registry داخلی هنگام دریافت `yocto-queue@0.1.0` قابل تکمیل نبود؛ این خطا مربوط به دسترسی مخزن پکیج محیط است، نه خطای TypeScript پروژه.
