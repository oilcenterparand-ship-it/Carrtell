# Carrtell — Sprint V4.7: ساده‌سازی سرویس‌کار و تخصیص سفارش

## هدف
این Sprint دوگانگی قدیمی `driver / technician / profiles` را از مسیر عملیاتی حذف می‌کند.
از این نسخه، سرویس‌کاری که حساب ورود دارد همان فردی است که در لیست تخصیص سفارش دیده می‌شود.

## مسیر ساده جدید
1. مشتری رزرو و پرداخت می‌کند.
2. مدیر وارد **مدیریت → درخواست سرویس** می‌شود.
3. سفارش را پیدا می‌کند.
4. در باکس **تخصیص سریع مأموریت** سرویس‌کار را انتخاب می‌کند.
5. خودروی سرویس اختیاری است؛ اگر خودرو تعریف نشده باشد باز هم می‌توان سرویس‌کار را تخصیص داد.
6. روی **تخصیص و ارسال به سرویس‌کار** می‌زند.
7. همان سفارش در پنل همان سرویس‌کار `/driver/dashboard` نمایش داده می‌شود.

## مدیریت سرویس‌کارها
صفحه جدید:
`/admin/technicians`

برای هر سرویس‌کار:
- نام و نام خانوادگی
- موبایل
- نام کاربری مستقل
- رمز مستقل
- محدوده سرویس‌دهی
- فعال / غیرفعال
- ویرایش رمز بدون ساخت حساب جدید

رمز خام در Frontend یا جدول عمومی ذخیره نمی‌شود؛ فقط hash در دیتابیس نگهداری می‌شود و Supabase Auth توسط Edge Function همگام می‌شود.

## مدیریت خودروهای سرویس
صفحه فعال‌شده:
`/admin/service-fleet`

خودرو می‌تواند سرویس‌کار پیش‌فرض داشته باشد، اما تخصیص خودرو برای مأموریت اجباری نیست.

## تغییر مهم در تنظیمات
در `/admin/settings` بخش ورود فقط برای **مدیر اصلی** باقی مانده است.
مدیریت نام کاربری/رمز سرویس‌کارها از این پس فقط از `/admin/technicians` انجام می‌شود تا دو سیستم مختلف ایجاد نشود.

## SQL لازم
فایل زیر را در Supabase SQL Editor اجرا کن:
`supabase/migrations/202608200001_service_operations_simplification.sql`

این migration:
- جدول `service_technicians` را ایجاد می‌کند.
- حساب فعلی technician را به اولین سرویس‌کار واقعی تبدیل می‌کند.
- جدول `service_fleet` را در صورت نبودن ایجاد/تکمیل می‌کند.
- RLS و دسترسی‌های لازم را تنظیم می‌کند.

## Deploy لازم
بعد از SQL:
```powershell
npx supabase functions deploy staff-password-login --no-verify-jwt
```

## تست
```powershell
npm run typecheck
npm run build
.\agent.ps1 PERSONAS
```

در Persona Admin مسیرهای زیر هم تست می‌شوند:
- `/admin/technicians`
- `/admin/service-fleet`
- `/admin/service-requests`
- `/admin/dispatch`

## تست دستی نهایی فقط بعد از PASS ایجنت
1. `/admin/technicians` → سرویس‌کار فعلی باید دیده شود.
2. یک سرویس‌کار جدید بساز.
3. `/admin/service-requests` → سفارش پرداخت‌شده را باز کن.
4. سرویس‌کار را انتخاب و تخصیص بده.
5. با نام کاربری همان سرویس‌کار وارد `/driver/login` شو؛ مأموریت باید در داشبورد خودش دیده شود.

## نکته امنیتی
- `SUPABASE_SERVICE_ROLE_KEY` فقط داخل Edge Function استفاده می‌شود.
- هیچ Secret جدیدی به Frontend اضافه نشده است.
- رمز خام سرویس‌کار در React ذخیره یا Persist نمی‌شود.
